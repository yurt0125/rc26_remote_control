# 7-4 接收机启动命令转发修改说明

> 实际修改日期：2026-07-04  
> 协议修订日期：2026-07-06  
> 涉及工程：遥控器 STM32F4、接收机 STM32H7

本文档记录“接收机启动后向遥控器发送一次命令，再由遥控器转发给串口屏”的全部修改。目标是在不修改串口屏工程、不改变原有周期数据帧和按键命令行为的前提下，实现启动命令 `(command=2, load1=0, load2=0)` 的可靠转发。`command=1` 保留给原有红外绑定功能。

## 一、功能行为

- 遥控器先上电，接收机启动并初始化 LoRa 后发送一次启动命令。
- 接收机到遥控器的无线帧为：`55 EE 02 00 00 D3 ED`。
- `0xD3` 是对 `02 00 00` 使用现有 CRC8-DVB-S2 算法计算出的 CRC。
- 遥控器校验帧头、CRC和帧尾后，将命令交给 HMI 模块。
- 串口屏当前处于 page 2 或 page 3 时，立即发送：`55 EE 02 00 00 0E`。
- 串口屏处于其他页面时暂存命令，首次进入 page 2 或 page 3 后发送一次。
- 成功加入 HMI TX FIFO 后清除待发标志，后续页面切换不会重复发送。
- HMI TX FIFO 暂时无空间时保留待发标志，由 HMI 周期任务继续重试。

## 二、接收机工程修改

工程路径：

`接收机h7代码/R1/RC10_LIB-FrameWork-main-v3/RC10_LIB-FrameWork-main`

### 1. 新增反向 HMI 命令帧

文件：`RC10_LIB/Module/Inc/Module_communication.h`

新增 7 字节紧凑帧：

```cpp
typedef struct {
    uint8_t header[2]; // 0x55 0xEE
    uint8_t command;
    uint8_t load1;
    uint8_t load2;
    uint8_t crc;
    uint8_t tail;      // 0xED
} HmiCommandFrame_t;
```

同时新增内部发送接口：

```cpp
void Comm_SendHmiCommandToTxBuffer(uint8_t command,
                                   uint8_t load1,
                                   uint8_t load2);
```

### 2. 组帧并复用现有发送链路

文件：`RC10_LIB/Module/Src/Module_communication.cpp`

`Comm_SendHmiCommandToTxBuffer()` 完成以下操作：

- 填充帧头 `0x55 0xEE`。
- 填充 `command/load1/load2`。
- CRC覆盖范围为三个业务字节，即 `sizeof(HmiCommandFrame_t) - 4`。
- 帧尾使用接收机回传方向现有的 `0xED`。
- 通过 `Comm_SendAnyDataToTxBuffer()` 加入现有 TX FIFO，继续复用 AUX、DMA、DCache处理和发送错误恢复逻辑。

### 3. 启动时发送一次

文件：`RC10_LIB/Module/Src/Module_lora.cpp`

在 `Lora_communication::Init()` 完成 ReceiveToIdle DMA 初始化及 HT 中断关闭后调用：

```cpp
Comm_SendHmiCommandToTxBuffer(2U, 0U, 0U);
```

该调用每次接收机启动只执行一次，不增加周期重发或应答协议。原有 `HMI_ButtonTransmitFrame(1, 0, 0)` 及其 `55 EE 01 00 00 0E` 红外绑定命令保持不变。

## 三、遥控器通信模块修改

工程路径：

`遥控器32f4主控代码/remote_control_twolora_puls`

### 1. 增加接收帧定义

文件：`App/communication.h`

新增与接收机完全一致的 `CommHmiCommandFrame_t`，字段顺序、长度、CRC位置及帧尾保持一致。

### 2. 支持长短两类回传帧

文件：`App/communication.c`

原接收解析循环只在 FIFO 中至少存在一帧 `XYZFrame_t` 时运行。现在将循环门槛调整为较短的 `CommHmiCommandFrame_t` 长度，并分别处理：

- `0x55 0xAA`：原有 XYZ 数据帧。若数据不足完整 XYZ 帧则等待下一批数据。
- `0x55 0xEE`：新增启动命令帧，长度为 7 字节。

启动命令帧验证逻辑：

```c
tail_ok = (pFrame->tail == 0xED);
crc_ok  = (pFrame->crc == crc8(frame_buf + 2,
                                sizeof(CommHmiCommandFrame_t) - 4));
```

校验成功后调用：

```c
HMI_ForwardReceiverCommand(pFrame->command,
                           pFrame->load1,
                           pFrame->load2);
```

CRC或帧尾错误时不转发，并增加现有 `rx_crc_error_cnt`。原 `0x55 0xAA` XYZ 数据帧的结构、字段、CRC和转发逻辑均未修改。

## 四、遥控器 HMI 模块修改

### 1. 增加独立待发状态

文件：`App/tjc_huart_hmi.h`

`HMIContext` 新增：

```c
uint8_t receiver_command_pending;
uint8_t receiver_command;
uint8_t receiver_command_load[2];
```

新增接口：

```c
void HMI_ForwardReceiverCommand(uint8_t command,
                                uint8_t load1,
                                uint8_t load2);
```

这组状态只服务于接收机启动命令，不改变原 `HMI_ButtonTransmitFrame()` 的页面门控语义。

### 2. page 2/3 转发及暂存

文件：`App/tjc_huart_hmi.c`

- `HMI_ForwardReceiverCommand()` 保存命令并置位待发标志。
- `HMI_TryForwardReceiverCommand()` 仅在 `hmi_state == 2` 或 `hmi_state == 3` 时尝试发送。
- HMI页面帧更新 `hmi_state` 后立即检查待发命令。
- `HMI_Task_Loop()` 每轮也会检查一次，使 TX FIFO 满时能够在空间释放后重试。
- 新增 `HMI_EnqueueButtonFrame()`，发送给屏幕的格式仍为：

```text
55 EE command load1 load2 0E
```

- 只有完整帧具备足够 FIFO 空间并成功入队后，才清除 `receiver_command_pending`。

## 五、未修改的功能

- 未修改串口屏工程。
- 未修改遥控器到接收机的 `0xAA 0x55` 摇杆帧、`0xAA 0x66` 设置帧和 `0xAA 0x77` 命令帧。
- 未修改接收机到遥控器的原 `0x55 0xAA` XYZ状态帧。
- 未修改摇杆、按键、拨杆、KFS、机器人状态及页面字段语义。
- 未修改现有 LoRa AUX、DMA、FIFO和超时恢复机制。
- 原 `HMI_ButtonTransmitFrame()` 从其他业务调用时仍只在 page 2/3 发送，不会因本次修改而在其他页面自动暂存。

## 六、初始页面统一为 page 2

2026-07-06补充修改：遥控器和接收机的软件初始页面状态统一设为数据显示页 `page=2`。

### 遥控器

- `Common/Datapool.c`：全局 `hmi_state` 初始值由 `0` 改为 `2`。
- `App/tjc_huart_hmi.c`：`HMI_Task_Init()` 中显式设置 `g_HMI.page_id = 2`。
- 串口屏后续上报合法页面帧时，仍会正常覆盖 `hmi_state` 和 `g_HMI.page_id`。

### 接收机

- `RC10_LIB/Module/Src/Module_communication.cpp` 中的 `rec_page` 已经是 `2`，保持不变。
- `RC10_LIB/Module/Src/Module_lora.cpp` 构造函数新增 `airjoy_data.page = 2`，保证首个遥控器数据帧到达前，上层读取的页面值也是2。
- 收到合法摇杆帧后，页面值仍由遥控器帧中的 `page` 字段正常覆盖。
